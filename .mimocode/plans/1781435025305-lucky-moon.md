# Fix 17 Failing CI Checks

## Root Causes (5 distinct issues)

### 1. `pnpm-lock.yaml` has 521 unresolved merge conflicts
Merge markers (`<<<<<<< HEAD`, `=======`, `>>>>>>>`) throughout the lockfile cause `ERR_PNPM_LOCKFILE_CONFIG_MISMATCH` on every `pnpm install --frozen-lockfile`.

**Affects ~9 jobs:** CI syncpack, node-tests, node-coverage, license-compliance + standalone Coverage, Release, Snyk, SDK E2E workflows.

### 2. Frontend submodule checkout fails in CI
`git submodule update --init --recursive` fails with `upload-pack: not our ref 6e83375...` because `actions/checkout@v4` uses a shallow clone by default and the separate submodule step lacks auth context.

**Affects 4+ jobs:** CI test, build, lint, sdk-types-sync + Coverage workflow.

### 3. `docs-deploy.yml` is wrapped in markdown code block
File starts with `` ```yaml `` on line 1, making it invalid YAML that GitHub cannot parse.

### 4. `packageManager` field says `yarn@4.16.0`
All CI workflows use pnpm. The mismatch causes warnings and potential corepack issues.

### 5. Upptime workflow: `GITHUB_TOKEN` passed incorrectly
`upptime/uptime-monitor@master` expects the token via `env:`, not `with:`. Current config passes it as an action input which gets ignored.
