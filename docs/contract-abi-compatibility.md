# Contract ABI Compatibility Check — Issue #806

## Overview

This document describes the cross-cutting compatibility check that ensures the
SDK, CLI, and indexer stay in sync with the deployed smart contract ABI/spec.

## Current State

The contract spec artifact (`docs/contract-spec.json`) is tracked as a
contract-repo issue and is not yet available. Once the contract repo publishes
the spec JSON, this check will be wired into CI.

## Planned Implementation

A test in `tests/contract-abi-compat.test.ts` will:

1. Load `docs/contract-spec.json` (or generate it from the WASM if unavailable).
2. Parse the contract's exported methods and types.
3. Cross-check against:
   - `packages/sdk/src/clients/InvoiceClient.ts` — method names and signatures
   - `cli/src/commands/*` — command definitions and flags
   - `indexer/src/event-parsers/*` — event parsing logic
4. Fail loudly if any consumer drifts from the spec.

## CI Trigger

The check runs when:
- `docs/contract-spec.json` changes
- `packages/sdk/src/clients/**` changes
- `cli/src/**` changes
- `indexer/src/**` changes

## Interim Baseline

Until the contract spec is available, this directory contains only this
documentation. The test will be enabled via a feature flag once the underlying
artifact exists.

## Generated Types Drift Guard — Issue #1033

Two checked-in surfaces derive from the Soroban contract spec:

- `sdk/src/generated/types.ts` — generated by `scripts/generate-types.ts`
  (`pnpm generate:types`)
- `packages/shared/src/types.ts` — generated by `scripts/generate-shared-types.mts`
  (`pnpm generate:shared-types`)

Both generators are **deterministic**: the build timestamp was removed from the
output header so a clean checkout always regenerates byte-identical files
(a spec hash and SDK version are embedded instead). This is what makes drift
comparison meaningful in CI.

`scripts/check-generated-types-sync.mjs` (`pnpm check:generated-types`) enforces
two layers of drift protection and never writes to the worktree:

1. **Inventory guard (always on)** — requires the SDK generated file to keep its
   `AUTO-GENERATED` marker, and treats any type that exists in
   `packages/shared/src/types.ts` being re-defined with a different shape in
   `sdk/src/generated/types.ts` as drift. It complements
   `scripts/check-no-duplicate-types.mjs`, which intentionally skips
   auto-generated files.
2. **Regeneration guard (when a contract spec exists)** — when
   `backend/target/spec.json` is present, both generators are run in dry-run mode
   and the output is byte-compared against the committed files.

CI wiring:

- The `sdk-types-sync` job builds the contract (when the backend submodule is
  initialized), regenerates both files, and fails if either file changed.
- The `generated-types-drift` job runs `pnpm check:generated-types` on backend and
  SDK/shared changes, so the inventory guard fires even when no spec is available
  in the checkout.

Run `pnpm test:generated-types` to exercise the generators' determinism and the
inventory guard locally.
